# Watching the ada session

A Claude session named `walks` runs on ada, unattended. It works the
queues in [2026-11-21-ada-autonomous.md](2026-11-21-ada-autonomous.md) and
then [2026-11-21-ada-next.md](2026-11-21-ada-next.md), and pushes and
releases on its own.

You are the watcher, not a second worker:
- Do not push to a repository it is working in. Leave its items alone.
- Answer the owner and pass on what they decide.
- Do the laptop-only work below.
- Take over only if the session has died.

## Checking on it

- **Is it alive:** `ssh ada`, then `screen -ls` or `tmux ls` for `walks`.
  - Attach with `screen -r walks` or `tmux attach -t walks`.
  - The owner's login starts tmux, so screen inside it takes `Ctrl-a a d`
    to detach.
  - If the ssh master drops, a new login needs the owner:
    `! ssh -fN -o ControlPersist=yes ada`.
- **What it has done:** `git pull` gfa-to-tabix and read the
  "Progress on ada" section of each ada handoff. The session keeps them
  current and pushes after each item.
- **Releases:** `npm view <pkg> version` for `@jbrowse/graph-walks`,
  `@jbrowse/bandage-core`, `@jbrowse/tubemap-core` and
  `jbrowse-plugin-graphgenomeviewer`. Also crates.io for gfa-to-tabix, and
  `https://jbrowse.org/plugins/jbrowse-plugin-graphgenomeviewer/latest/package.json`.
- **CI:** `gh run list -R GMOD/<repo> -L 3`. The tube map's repository is
  `cmdcolin/sequenceTubeMap`.
- **If it died:** start a new one on ada.
  - It resumes from the handoffs.
  - Run it in `~/work/handoff-1121/gfa-to-tabix`:
    `CLAUDE_CONFIG_DIR=~/.claude ~/.local/bin/claude --model claude-opus-5-5 --dangerously-skip-permissions "$(cat ~/work/handoff-1121/PROMPT.md)"`.
  - `~/.claude` on ada has Opus and Fable. `~/.claude2` was out of weekly
    usage until Nov 22, and `~/.claude3`'s login has expired.

## The owner's calls, with what is known

- **Per-group units** (`docs/placement/scale-past-464.md`, "Proposal for the
  owner"): not recommended. A format 9 for a gain that only shows past a
  few thousand haplotypes. The owner agreed 5,000 is stretching this
  design; a much larger cohort would want a different approach (shared
  runs, as GBWT).
- **The node cap** (graph-walks branch `node-limit-preset`, held). The
  owner questioned the caps:
  - With every haplotype, the step budget refuses first.
  - With four, 1–10 Mb windows reach 26,000–440,000 nodes.
  - The second queue measures layout and draw time against node count, and
    studies an overview tier instead of refusing.
- **The forms track's row labels:** core JBrowse cuts them at about 20
  characters (`ROW_LABEL_MAX_EMS`, jbrowse-components, the owner's repo).
  `agent-docs/ideas/waiting-on-a-call/forms-row-label-width.md`.
- **jb2hubs on graph-walks 9:** its own session (`jb2hubs-ae`) was asked to
  move it; it needs exact lengths in its sidecar to follow the naming rule

## When the ada session is done

Its handoffs hold its report. Check that every released version is on npm
and its CI green. Tell the owner what landed and what waits on them. Then
delete this file and the ada handoffs once their leftovers are filed in
`todo/` or `ideas/`, and delete the `ada-session-running` memory.
